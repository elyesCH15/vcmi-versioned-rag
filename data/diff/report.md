## 6. Change IDs, events and shortlist

**change_id.** `c-` followed by the first 10 hex characters of SHA-256 over the canonical serialisation `json.dumps([from_version, to_version, section_id, old_text, new_text], ensure_ascii=False, separators=(',', ':'))` encoded as UTF-8 (missing text is JSON null). Records with identical content in the same pair and section get their occurrence number (2, 3, ...) appended to the list before hashing, in record order. If two different serialisations share the 10-hex prefix, every record in that clash uses 16 hex characters instead. **Events** (`events.jsonl`). Records are grouped within each version pair (never across pairs) by the union of these rules; every record belongs to exactly one event. `event_id` is `e-` plus the first 10 hex characters of SHA-256 over the JSON list of sorted member change_ids. Event type is `status` if any member is status, else `substantive` if any member is substantive, else `editorial`. Summaries are generated from the rule that formed the event; the 30 shortlisted events carry hand-written summaries.

- R1 status: all `status` records of a version pair form one event (they all express the same change in whether VCMI Claims are issued).
- R2 number/date move: a `modified` record whose full dates or percentages differ defines moved values (old value -> new value). Every record of the pair that carries one of those moved values on the matching side (old text for the old value, new text for the new value; removed records on the old side, added records on the new side) joins the same event.
- R3 same edit in several places: `modified` records of a pair with the same word-level edit (identical multiset of removed and added words after terminology normalisation, with at least one content word) form one event; so do `added` (or `removed`) records with identical comparison text.
- R4 whole section: records whose note says the whole section was added (or removed) form one event per section.
- R5 Document History row: records of the same Document History row form one event.
- R6 terminology swap: editorial records whose only difference is a terminology swap form one event per pair and swap (e.g. 'VCMI Silver' -> 'Carbon Integrity Silver').
- R7 singleton: every other record is its own event.
